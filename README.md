# 墨引 · 小说 AI 工坊

一个**可安装到手机桌面、零依赖、本地运行**的小说创作工作台。你把一句灵感交给它，它按「世界观 → 人物 → 资料库 → 大纲 → 文风 → 正文 → 导出」七步帮你起草；每一步都可以手动修改、锁定，再让 AI 接着往下写。

- 文件：主体仍是单文件 `index.html`（HTML + CSS + JavaScript 全部内嵌，双击即用）；另附 `manifest.webmanifest`、`sw.js`、`icon.svg` 三个 PWA 附属文件
- 数据：只存在当前浏览器的 `localStorage`
- 模型：任何 OpenAI 兼容的 Chat Completions 接口，默认适配 DeepSeek
- 没有后端、没有账号、没有构建步骤、不加载任何第三方脚本
- 手机：通过 HTTPS 静态托管后可「添加到主屏幕」，以独立窗口打开

---

## 30 秒开始

1. 双击打开 `index.html`（推荐 Chrome / Edge 最新版）。
2. 首次打开是**演示模式**：不填 Key 也能把七步完整走一遍，所有按钮都能点。
3. 想用真实模型：点左下角「⚙ API 与偏好设置」，填入 API Key，保存。
4. 回到「世界观」，写一句核心灵感，点「生成完整世界观」。

> 演示模式生成的是内置示例文本，用来验证流程与界面；真实创作质量取决于你配置的模型。

## 手机与 PWA

### 为什么不能直接双击手机上的 HTML 安装？

PWA 的安装入口、Service Worker 离线缓存都要求页面通过 **HTTPS**（或电脑本机的 `localhost`）打开。手机上直接打开 `file://` 文件只能当普通网页用，不能安装。因此要把这四个文件放到一个静态网站空间：

```
index.html
manifest.webmanifest
sw.js
icon.svg
```

不需要 Node、不需要构建、不需要数据库；GitHub Pages、Netlify 等纯静态托管都可以。

> 本应用**不提供可下载的 `.apk` 文件**。Android 上的“安装应用”由 Chrome 根据 PWA 现场生成 WebAPK；iPhone 上是主屏幕快捷方式。要分享给别人，发送部署后的网址即可，不要发送网页文件或改后缀的假 APK。

### 方案 A：GitHub Pages（免费）

1. 登录 GitHub，新建一个仓库（公开或私有均可，Pages 免费版通常要求公开仓库）。
2. 把 `novel-ai-studio` 文件夹里的四个文件上传到仓库**根目录**（不要只上传 index.html）。
3. 打开仓库 **Settings → Pages**，Source 选 **Deploy from a branch**，分支选 `main`，目录选 `/ (root)`，保存。
4. 等 1–2 分钟，页面顶部会出现 `https://你的用户名.github.io/仓库名/`。
5. 手机浏览器打开这个网址。Android Chrome：右上角菜单 →「安装应用」或「添加到主屏幕」；iPhone Safari：底部「分享」→「添加到主屏幕」。
6. 安装后从桌面图标打开，会以独立窗口运行；断网时仍能打开应用外壳（AI 生成需要联网）。

### 方案 B：Netlify Drop（最快）

1. 打开 Netlify，进入 “Deploy manually / Drop”。
2. 把包含四个文件的文件夹拖进去。
3. 得到 `https://随机名.netlify.app` 后，用手机打开并按上面的方式安装。

### 手机端已做的适配

- 顶栏在窄屏收成：品牌、作品切换、安装、新建、设置；状态徽章收成小圆点。
- 步骤导航横向滚动；七个页面、资料库人物框、弹窗和正文编辑器都改为单列。
- 输入框在手机上使用 16px 字号，避免 iOS 聚焦时自动放大；按钮和步骤项加大触控高度。
- 弹窗限制在可视区域内，内容区独立滚动，底部按钮可换行；适配刘海屏安全区。
- 正文编辑器在手机上保持至少 56vh 的写作高度。

### 第一次在手机上打开：跟着 5 页引导走

页面在手机宽度下首次打开时，会自动弹出「手机使用指引」，用 5 页讲清手机上怎么开始：

1. **七步流程**：顶部步骤条可以横向滑动，世界观 → 人物 → 资料库 → 大纲 → 文风 → 正文 → 导出。
2. **先决定用不用 AI**：设置里填 Base、模型和 Key；没有 Key 也可以先用演示模式走一遍。
3. **资料库**：粘贴或导入人物、技能、世界观材料，识别后会生成人物框和条目。
4. **正文**：直接贴一张单章大纲，设目标字数，标题留空会自动生成。
5. **安装与备份**：Android/iOS 安装到桌面；作品只存在本机，记得用 JSON 备份。

关闭后不再自动出现；之后可从「设置 → 安装到手机桌面 → 查看手机使用指引」重新打开，PWA 安装帮助弹窗和「关于」里也有入口。

### 数据迁移（很重要）

`file://` 打开的本地文件和 `https://` 部署后的网站属于**不同的浏览器存储空间**，作品不会自动跟过去。迁移步骤：

1. 在原来双击打开的页面里，进入「07 导出」，导出项目 JSON。
2. 在手机/线上页面里，点侧栏「导入项目 JSON」，选择刚才的文件。
3. API Key 不会随 JSON 导出，需要在线上页面重新填一次。

以后固定用同一个网址打开，作品就会一直保存在该网址的 `localStorage` 里。

### 更新后看不到新版本？

Service Worker 会优先走网络获取 `index.html`，一般刷新一次即可。如果仍是旧版，关闭所有该站点的标签页再打开；开发者可在 `sw.js` 顶部把 `CACHE = 'moyin-pwa-v1'` 改成新版本号，强制清理旧缓存。

### 跨域（CORS）不会因为部署而消失

部署到 HTTPS 只解决安装与缓存；浏览器调用 DeepSeek 是否被 CORS 拦截，仍取决于服务商是否允许网页直连。如果「测试连接」报 `Failed to fetch`，而 curl 能通，请按下面 API 配置里的 CORS 说明，自建一个允许跨域的转发地址。**不要把 Key 交给公共在线代理。**

## API 配置

默认值：

| 配置项 | 默认值 |
| --- | --- |
| Base URL | `https://api.deepseek.com` |
| 模型 | `deepseek-flash` |
| 温度 | `0.85` |

说明：

- DeepSeek 官方当前推荐 `https://api.deepseek.com`（**不需要** `/v1`），模型 `deepseek-flash`，也可以填 `deepseek-v4-pro`。模型与地址可能随官方调整，以 [DeepSeek API 文档](https://api-docs.deepseek.com/) 和你的控制台为准。
- 旧配置 `https://api.deepseek.com/v1` + `deepseek-chat` 会在读取本地存档时自动升级为上面这组默认值；如确需旧接口，可在设置里保存后手动填回，但官方已不把它作为默认推荐，不保证长期可用。
- 任何 OpenAI 兼容服务都可以接入：本地 Ollama、OneAPI 网关、其他云厂商的兼容端点等。把 Base URL 指到对应的 `/chat/completions` 路径即可。
- 对 DeepSeek 接口，应用会显式传 `thinking: { type: "disabled" }`。这是为了避免思考模式把 `max_tokens` 全耗在 `reasoning_content` 上，导致最终 `content` 为空、结构化生成报“无法解析 JSON”。如果你接入的是别的服务商，不会带这个字段。
- API Key 只写入本机 `localStorage`，不会随项目 JSON 导出。调用时，提示词会直接发送到你填写的服务商，本工具不经过任何中间服务器。
- **浏览器跨域（CORS）提示**：部分 API 服务不允许网页直接跨域调用。如果「测试连接」报网络错误 / `Failed to fetch`，但用 curl 能通，通常就是 CORS。解决方式是自建一个允许 CORS 的本地或服务端转发，把 Base URL 改为该转发地址。**不要把 API Key 交给公共在线代理或来路不明的中转站**，那等于把 Key 公开。

## 七步流程

### 01 世界观

填写作品名、题材、一句灵感，点「生成完整世界观」。会得到 7 个字段：

时代背景、地理格局、势力组织、规则体系、社会文化、核心冲突、故事基调。

每个字段都可以直接编辑；点字段右上角的锁，可以防止「生成完整世界观」覆盖它。单字段不满意，用「重写本项」让 AI 只改这一块。

### 02 人物

「生成核心人物」一次生成 4 个角色，包含身份、外貌、性格、动机、秘密、成长弧、关系。可以单独重写某个角色（保留姓名与角色定位）、新增、删除。角色也可以锁定；批量重生成时只会替换未锁定的角色，锁定的原样保留。

页面上还有一块「人物关系网」，用文字梳理谁和谁互相利用、谁欠谁、谁知道谁的秘密。

**人物形象注入**：点「◈ 形象注入」或人物卡上的「形象注入」，可以：

- 直接按 `Ctrl+V` 粘贴一张人物图片；
- 把图片拖进弹窗，或点「选择文件」上传 JPG / PNG / WebP；
- 也可以粘贴一段人物设定文字，或上传 TXT / Markdown 角色卡。

AI 会读取图片/文字，整理成姓名、身份、外貌、性格、动机、秘密、成长弧、关系，并写入「新建人物」或你选中的已有角色卡。图片会自动压到 420px 的本地缩略图，跟在人物卡上显示；**图片和文字都只在本机处理，发送给模型时才会随请求带出**。图片看不出的信息（比如秘密、成长弧）会留空，不会硬编。

> 形象注入需要配置 API Key。演示模式没有识图能力，点击识别时会提示先接入模型。建议使用支持图片输入的 `deepseek-flash`（本应用默认模型）。

### 03 人物资料库

把「大杂烩」材料整段粘进来：人物小传、技能表、物品来历、宗门关系、历史传闻、零散灵感都可以。也可以上传 `txt / md / json / csv` 文本文件。

- 粘贴后点「识别并入库」。
- **选择文件后会直接自动识别**（需先配置 API Key），不需要再点按钮。演示模式仍可手动点按钮看内置示例。

识别分两步：先拆七类条目（总计上限 100 条；材料长时自动分段，每段最多 30 条），再单独整理人物卡与世界观，避免一次输出太多被截断。第二步会把材料里**所有有姓名/固定称呼的人物**整理成人物卡（不只主角，戏份少也会收），自动补进「人物」模块；把材料明确涉及的时代、地理、势力、规则、社会、冲突、基调补进「世界观」的空字段。已有同名人物只补空字段，不覆盖你手写的内容；锁定的人物和世界观字段会跳过。资料库固定**按人物一框展示**：技能、武魂、物品等若材料写明归属，会自动收进对应人物框内，人物框里分「技能/底牌」「物品/装备」小节，点开可看效果、代价与限制，不再单独成为一张技能卡。单次最多整理 100 条资料、50 个人物，适合中长篇的大杂烩材料；单次送入模型的原文最多 2 万字，超长材料建议分批投喂，避免漏掉后半段人物。

AI 只提取材料里**明确写到**的内容，拆成七类条目：

- 人物：身份、外貌、性格、动机、秘密、关系
- 技能：掌握者、效果、代价、限制
- 物品：来历、能力、持有者
- 势力：目标、成员、资源、敌对关系
- 地点：位置、规则、危险、出入方式
- 规则：世界运行规则、禁忌与例外
- 其他：历史、传闻、伏笔

材料里没写的字段会标「未提及」，不会替作者补完。同名或同别名的条目会合并补充，不会重复堆叠。识别完成后会提示这次自动补了几个人物、补了哪些世界观字段。

**为什么要有资料库**：它是「事实层」，人物卡是「叙事层」。写大纲、写正文时，资料库会作为权威设定进入提示词；默认开启「写作严格依据资料库」，模型不得给角色新增未记录的能力、道具，也不得违反已记录的代价。剧情确实需要新设定时，提示词要求模型标出 `【待补：……】`，而不是偷偷编一个。

- 条目可以手动增删改，支持按名称/别名/摘要/标签搜索，按类型筛选。
- 原始资料会保留在项目里；识别失败也不会丢，可以稍后重试。
- 关闭右上角的严格开关，资料库就只作参考。

### 04 大纲

- **整本分卷大纲**：一句话故事 + 全书主线 + 3 卷 × 4 章细纲。

生成后可以继续「补 4 章」、手动增删卷章、改章节名与细纲。每章后面的「写正文」会直接跳到写作页并选中该章。

如果你手里已经有这一章的单张大纲，不需要先来大纲页建章：直接去「06 正文」，用顶部的「直接贴大纲，写这一章」即可。

### 05 文风库

内置 13 种按题材划分的文风预设，覆盖：玄幻升级流、仙侠古典、都市日常、都市异能、悬疑灵异、科幻硬核、历史权谋、古代言情、现代言情、无限流/系统、武侠、军事、轻小说。

每种文风包含：

- 名称、适配题材、一句话气质
- 文笔画像：人称、节奏、句式、对话、描写侧重、收尾钩子、应避免的写法
- 一段原创示例
- 给模型的写作指令

你还可以创建**自定义文风**：写一段描述，或贴一段样本文字，让 AI 提炼成可复用的文风卡。自定义文风与预设一样能设为项目主文风，也能被单章覆盖。

项目有一个「主文风」；每章还可以单独指定另一个文风。强度分弱 / 中 / 强，控制模型在多大程度上贴合该文风。

### 06 正文

**直接贴大纲，写这一章**：页顶有一张「单章直写」卡片。把这一章的大纲原样粘进去，填「本章目标字数」（500–6000，留空继承项目默认），点「按此大纲写正文」——会新增一章，并严格按你贴的大纲和字数生成正文，不需要先在大纲页生成章节。标题可以留空：系统会先按大纲起一个临时名，正文写完后根据正文内容自动取标题；「自动标题字数」可选 1–24 字。填了标题就沿用你填的。生成时同样带入世界观、人物、资料库与前情。

编辑器标题旁有「目标 __ 字」输入框：本章想写多少字，直接填（500–6000）。留空则使用项目默认值（新建作品时可设置，默认 2200 字）。这个数字会进入提示词，生成与续写都按它控制篇幅，同时自动调整模型输出上限。标题旁还有「标题 __ 字」选择器和「按正文取标题」按钮：选好目标字数，可以随时按当前正文重新取标题。

- **生成本章**：按本章细纲、世界观、人物、资料库和前情写目标字数（允许 ±15%）；已有正文时会先确认是否覆盖。
- **续写**：从当前正文结尾接着写约「目标字数」，同样受资料库与前文约束。
- **润色重写**：不改情节与信息，只优化节奏、画面、对话和语言；先预览，满意再采用。
- **换文风重写**：按当前章节文风重写；同样先预览。
- 生成过程是流式的，可以随时点「■ 停止」，已生成的部分会保留。
- 生成期间编辑器只读，避免你的输入和流式输出互相覆盖。

## 存档、导出与导入

- 所有改动自动保存到 `localStorage`，键名：`moyin.novel.studio.v1`。关闭页面、刷新、重启浏览器都不会丢。
- 顶部下拉框可以创建、切换多个作品；每个作品有独立的设定、大纲、正文。
- 「导出」页可以：
  - 下载 Markdown（世界观 + 人物 + 资料库 + 大纲 + 已写正文），用于投稿排版或继续加工；
  - 导出项目 JSON（包含设定、人物、资料库、大纲、正文、自定义文风），用于备份或换设备；
  - 从 JSON 导入：会新增一个独立项目，不覆盖现有作品；重名会自动加「（导入）」。
- 项目 JSON **不包含 API Key**。
- 清除浏览器站点数据会删除本地作品，请定期导出备份。

## 常见问题

**打开后页面空白 / 按钮没反应？**
确认文件完整（`index.html` 应约 100 KB 以上），用 Chrome 或 Edge 打开；不要用记事本内置预览。浏览器控制台若有红色报错，请把报错信息一并反馈。

**测试连接失败？**
依次检查：Key 是否复制完整、Base URL 是否为 `https://api.deepseek.com`、模型名是否为 `deepseek-flash`、账号是否有余额。若 curl 能通而浏览器不通，见上面的 CORS 说明。

**报 401 / 402 / 429 / 404？**
401：Key 无效；402：余额不足；429：频率或额度受限；404：Base URL 或模型名不对。界面会把服务端返回的前 300 个字符显示出来，便于排查。

**生成大纲或识别资料时提示“模型返回的内容无法解析为 JSON”？**
先点弹窗里的「重试」。如果仍失败：

1. 确认 Base URL 是 `https://api.deepseek.com`，模型是 `deepseek-flash`；
2. 应用已对 DeepSeek 关闭思考模式。若你手动改过接口，请确认没有把 `thinking` 强制设为 `enabled`；
3. 生成大纲时先重试；仍失败可改用写作页的「直接贴大纲，写这一章」，绕过整本大纲。识别资料时把文件拆小（一次投喂一批人物/技能），避免输出被截断；
4. 若错误信息里出现 `finish_reason=length`，就是输出长度不够。资料库现在分两步识别，条目阶段还会按 4000 字左右自动分段（每段最多 30 条），就是为了降低单次输出压力；超大材料仍建议按人物/势力分批。

**生成到一半停了？**
可能是网络中断、额度用完或你点了停止。已生成的内容会保留；可以直接再点「续写」，或重新生成。真实 API 下重新生成会先确认是否覆盖。

**换电脑怎么迁移？**
在旧电脑导出项目 JSON，在新电脑打开 `index.html`，用「导入 JSON」导入。API Key 需要在新电脑重新填一次。

**文风会不会抄某位作者？**
预设只描述「写法特征」（人称、节奏、句式、对话、描写侧重、钩子、禁忌），示例为原创演示段落；自定义文风只提炼风格特征，不要求模型复刻原文。请勿把受版权保护的整段作品用于生成或传播。

## 文件说明

```
novel-ai-studio/
├─ index.html            # 应用本体（单文件，双击即可运行）
├─ manifest.webmanifest  # PWA 名称、图标、启动方式
├─ sw.js                 # Service Worker：只缓存应用外壳
├─ icon.svg              # 应用图标
```

`index.html` 单独拷走仍能和以前一样双击使用；后三个文件只在通过 HTTPS 部署、需要“安装到桌面/离线打开”时才会用到。

## 技术备注

- 无构建、无 npm、无 CDN；样式与逻辑全部内嵌。
- 流式解析兼容标准 SSE：逐行读取 `data:`，忽略心跳与不完整片段，遇到 `[DONE]` 结束。
- 结构化生成会先展示原始流，再尝试解析 JSON；失败会给出重试，不会把半截 JSON 写进设定。
- 导入的 JSON 会经过字段归一化（缺失字段补空、类型纠正、过滤非法项），降低畸形文件导致崩溃的概率。
- 人物形象图会先在浏览器里压到最长边 420px 的 JPEG，再以 data URL 存进 `localStorage` 和项目 JSON；图片较大时请留意浏览器存储配额。
- 资料库条目按类型控制长度（名称 ≤40、摘要 ≤260、详情 ≤1600 字），提取与导入时统一归一化；原始材料单份建议不超过 20 万字符。
- 章节目标字数优先级：本章 `wordTarget` > 项目 `wordTarget`（默认 2200），范围 500–6000；提示词按目标字数生成，`max_tokens` 按 1.8 倍目标 + 600 预留，最高 8192。
- 单章直写标题可留空：正文完成后用一次短请求按正文生成标题，目标字数可在 1–24 字间选（默认 12）；请求失败或没有 Key 时，自动取正文/大纲首句回退，不会卡住章节。编辑器里也可随时选字数并「按正文取标题」。
- 资料库文件导入后自动触发识别，识别分两步（先拆条目，再同步人物/世界观）；条目和人物阶段都会按材料长度自动分段（条目每段约 4000 字、每段最多 30 条；人物每段约 6000 字、每段最多 20 人），降低单次输出被截断的概率。人物只补空字段、锁定人物跳过，世界观只填未锁定且为空的字段，不覆盖已经手写的内容。某一段输出被截断时，可只重试该段，前面已识别的条目不会丢。
- PWA：`manifest.webmanifest` 提供独立窗口、主题色与图标；`sw.js` 只缓存 `index.html`、manifest、图标等同源外壳，导航请求网络优先、失败回退缓存；跨域 API 请求直接放行，不进入缓存。Service Worker 只在 HTTPS 或 localhost 注册，所以 `file://` 双击打开不会触发。
- 手机布局在 640px 以下切换：顶栏收起徽章文字和按钮文字、步骤横向滚动、表单与卡片单列、输入框 16px、弹窗限制在 `100dvh` 内并适配安全区。
- 自动保存有 450ms 防抖；`Ctrl/⌘ + S` 立即保存；`Esc` 关闭弹窗并中止正在进行的生成。
